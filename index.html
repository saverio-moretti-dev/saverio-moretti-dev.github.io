Import CSV che si può riportare indietro

In produzione da settembre 2026
Fig. 2.1 Percorso di una riga. La linea rossa tratteggiata è il ritorno indietro, possibile per import, modifiche di massa e cancellazioni.

APrima

L'import nativo di PrestaShop non si può annullare. Se il server va in timeout si ferma a metà, lascia dati orfani e non dice cosa è fallito.

BCostruito

Ogni riga in transazione, lavoro in cron a passo controllato, stato completo del prodotto salvato prima di toccarlo. L'anteprima mostra la pagina vera del prodotto, scritta e poi annullata.

CCollaudo

Stesso file importato con il nativo e con il mio, su una copia del sito: risultati identici campo per campo. Due errori JavaScript sono arrivati in produzione; corretti a ottobre, da allora provo l'interfaccia anche nel browser.

// reversibleimport · src/Importer.php (versione pubblica, scritta da zero)
public function apply(Plan $plan, string $fileName): int
{
    $this->catalog->begin();
    try {
        $batchId = $this->catalog->createBatch($fileName, count(...));
        foreach ($plan->changes as $change) {
            // Fra anteprima e conferma passano minuti: se il valore
            // è cambiato, l'anteprima non è più vera.
            $current = $this->catalog->currentValues($change->productId);
            if ($current === null || !$this->same(...)) {
                throw new StalePlanException($change);
            }
            $this->catalog->saveSnapshot($batchId, $change);
            $this->write($change->productId, $change->field, $change->after);
        }
        $this->catalog->commit();
    } catch (\Throwable $e) {
        $this->catalog->rollback();
        throw $e;
    }
    return $batchId;
}
  1. Prima di scrivere ricontrolla che il prodotto sia ancora come nell'anteprima: se qualcuno l'ha cambiato nel frattempo, si ferma.
  2. Salva la fotografia del valore vecchio: è quella che permette di tornare indietro.
  3. Se qualcosa va storto, si annulla tutto il blocco: non restano dati a metà.

Un gestionale senza API, collegato al sito

Automazione dal 2025; ponte e import dal back office, 2026
Fig. 4.1 Il ponte prende sugli articoli lo stesso blocco che mette il gestionale quando un collega li apre. Se due scritture si scontrano, la transazione si rifà da capo.

APrima

Il gestionale non ha API. Gli import di massa si facevano solo da Excel, con nessun altro collegato, e fallivano per un solo dato fuori formato. Niente controlli, niente annullamento.

BCostruito

Import e modifiche di massa anche con i colleghi collegati. La mappatura delle colonne impara gli abbinamenti e si salva come modello; l'anteprima simula il risultato sull'archivio vero; si ripristina una versione precedente sugli stessi prodotti.

CCollaudo

Prima di scrivere con i colleghi collegati ho studiato su un archivio di prova come reagisce il database con dodici utenti insieme.
