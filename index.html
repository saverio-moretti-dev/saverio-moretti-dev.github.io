Prima

Costruito

Collaudo

Stesso file importato con il nativo e con il mio, su una copia del sito: risultati identici campo per campo. Due errori JavaScript sono arrivati in produzione; corretti a ottobre, da allora provo l'interfaccia anche nel browser.

// reversibleimport · src/Importer.php
public function apply(Plan $plan, string $fileName): int
{
    $this->catalog->begin();
    try {
        $batchId = $this->catalog->createBatch($fileName, count(...));
        foreach ($plan->changes as $change) {
            $current = $this->catalog->currentValues($change->productId);
            if ($current === null || !$this->same(...)) {
                throw new StalePlanException($change);   // ①
            }
            $this->catalog->saveSnapshot($batchId, $change); // ②
            $this->write($change->productId, $change->field, $change->after);
        }
        $this->catalog->commit();
    } catch (\Throwable $e) {
        $this->catalog->rollback();                      // ③
        throw $e;
    }
    return $batchId;
}
  • ①Se qualcuno ha cambiato il prodotto dopo l'anteprima, si ferma.
  • ②Salva il valore vecchio: è ciò che permette di tornare indietro.
  • ③Se qualcosa va storto si annulla tutto il blocco: niente dati a metà.

Metodo

Progetto io, scrive Claude Code, verifico io.

Ogni modulo segue gli stessi passi, sempre nello stesso ordine.

  1. Studio

    Il lavoro e i processi dell'azienda, partendo dal catalogo: cosa si fa a mano, dove nascono gli errori.

  2. Progetto

    Logiche e flussi li decido io. Claude Code scrive la maggior parte del codice.

  3. Copia del sito

    Ogni modulo passa da una copia in Docker con dati veri, prima di toccare la produzione.

  4. Collaudo

    Test e confronto con il risultato atteso, campo per campo. Poi l'interfaccia nel browser.

  5. Produzione

    Con backup e ritorno alla versione precedente, sempre pronti.

Un sistema mio per lavorare con Claude Code su più progetti

Claude Code a ogni sessione riparte da zero, e io porto avanti più progetti insieme: plugin, musica, i miei strumenti. Ho costruito regole, strumenti e un archivio di conoscenze perché ogni sessione sappia da dove ripartire e cosa è già stato deciso.

  • 17repository tenute allineate da uno script mio
  • 3comandi miei per passare il lavoro fra sessioni: /superagente, /passaggio, /riparti
  • 1app mia per il consumo dei token: tetti per sessione e per giorno

Di chi è cosa

Claude Code è di Anthropic. Regole, struttura, strumenti in Python e app dei token li ho progettati io.

1 / 8

Conoscenze ad albero

Tutto ciò che si impara sta in stanze collegate a strati: una mappa, poi le stanze per argomento, poi le fonti. Ogni agente legge solo lo strato che gli serve: meno token, meno errori. Uno script segnala le stanze diventate vecchie.

mappastanzafonte

2 / 8

Superagente e agenti

Un agente per progetto, ognuno nel suo recinto: non legge i progetti degli altri. Il superagente coordina, distribuisce gli ordini, controlla le consegne e fa da tramite con me. Un ordine fra agenti vale solo se è scritto in un registro verificabile.

iosuperagenteagenti di progetto

3 / 8

Comandi miei

Tre comandi personalizzati per Claude Code. /passaggio scrive la nota per la sessione successiva. /riparti riprende da quella nota con il contesto minimo. /superagente ricrea il coordinatore e lo stato di tutti i progetti.

/passaggio/riparti/superagente

4 / 8

Prova cieca

Prima di consegnare un testo, un sito o una proposta, lo faccio giudicare da agenti «ciechi»: senza memoria, senza file, solo ricerca web. Ognuno interpreta un ruolo inventato, per esempio un titolare o un cliente diffidente, e dice cosa non lo convince. Poi verifico che la prova sia valida.

5 / 8

Processo a fasi

Per i compiti in cui un errore costa: un agente fa la ricerca e la salva, io approvo il piano, poi costruzione, prove cieche e consegna.

ricercapiano approvatocostruzioneprove ciecheconsegna

6 / 8

Ricerche mai ripetute

Ogni ricerca fatta finisce in un registro, con la sua conclusione. Prima di cercare di nuovo, uno script la ritrova: nessun agente rifà il lavoro di un altro.

ricercaregistroscript che la ritrova

7 / 8

Token razionati

Un'app mia misura il consumo per sessione e per settimana, mette tetti giornalieri e pianifica i lavori non urgenti prima del ripristino settimanale.

consumotettolavori pianificati

Imparare da me

Ogni correzione che faccio diventa una regola scritta che tutti gli agenti leggono. Il sistema si adatta a come lavoro io, e non ripete lo stesso errore.
